# AI Arena

AI Arena היא אפליקציה מקומית להשוואה, דיון, המשך שיחה וקבלת החלטות בעזרת כמה מודלי AI במקביל.
במקום לשאול מודל אחד ולקוות שהוא צדק, אפשר לתת לכמה מודלים לענות, להתווכח, לבקר אחד את השני,
להגיע לסיכום, ולשמור את כל התהליך בלוג שקוף.

## מה התוכנה עושה

AI Arena מאפשרת לעבוד עם כמה ספקי AI באותו ממשק:

- Claude
- Gemini
- ChatGPT
- Grok
- Perplexity

לא חייבים להשתמש בכולם. כל API key הוא אופציונלי. המערכת מפעילה רק את המודלים שחוברו בפועל.

## מצבי עבודה

### Compare Mode

במצב Compare המשתמש מכניס שאלה אחת, וכל המודלים המחוברים עונים עליה במקביל.
כל מודל עונה לבד, בלי לראות את התשובות של האחרים.

לאחר קבלת התשובות אפשר לבחור תשובה אחת ולהמשיך שיחה עם אותו מודל, או לעבור למודל אחר עם ההקשר הקיים.

מתאים ל:

- השוואה מהירה בין מודלים.
- בדיקת סגנון, עומק ודיוק.
- בחירת התשובה הכי טובה ידנית.
- המשך שיחה כמו צ'ט עם מודל נבחר.

### Debate Club

במצב Debate Club המודלים מנהלים דיון ביניהם.
כל מודל רואה מה המודלים הקודמים אמרו, מוסיף נקודת מבט, מתקן טעויות, מסכים או חולק,
ובסוף המערכת מנסה להגיע לתשובה מסכמת.

הדיון מוגבל במספר סבבים כדי לשלוט בעלויות:

- ברירת מחדל: 3 סבבים.
- מקסימום: 10 סבבים.

אם יש לפחות 3 מודלים מחוברים, אחד מהם יכול להישמר בתור שופט חיצוני.
אם המשתתפים לא מגיעים לתשובה טובה מספיק, השופט מחליט או יוצר תשובה משולבת.

לאחר שהדיבייט מסתיים, אפשר לשאול שאלת המשך ולהמשיך את אותו דיון. הלוג הקודם נשמר כהקשר,
המודלים ממשיכים להתדיין, ונוצרת תשובה מסכמת חדשה.

## בחירת מודלים

במסך `API Keys` אפשר לבחור איזה model ירוץ עבור כל ספק.
לדוגמה:

- Claude Sonnet / Haiku
- Gemini Flash / Pro
- GPT-4o / GPT-4o mini / GPT-4.1
- Grok
- Perplexity Sonar

הבחירה נשמרת בדפדפן ומשמשת גם לקריאות בפועל וגם לחישוב עלויות משוער.

## תפקידי מודלים בדיבייט

ב-Debate Club המודלים מקבלים תפקידים כדי שהדיון יהיה איכותי יותר:

- Research lead - מתמקד בעובדות, מקורות ואימות.
- Critical reviewer - מאתגר הנחות חלשות וסיכונים.
- Synthesizer - מחבר את הנקודות החזקות לתשובה אחת.
- Strategy lens - מתמקד בהחלטות, tradeoffs וצעדים הבאים.

## שקיפות ולוג

כל דיון נשמר בלוג שקוף:

- מי אמר מה.
- באיזה סבב.
- מה הייתה החלטת הקונצנזוס.
- האם הופעל שופט.
- מה התשובה הסופית.
- מה נאמר בשאלות המשך.

אפשר לייצא את הלוג לקובץ טקסט.

## היסטוריה

האפליקציה שומרת היסטוריית sessions מקומית בדפדפן:

- Compare sessions.
- Debate sessions.
- תשובות סופיות.
- לוגים מלאים.
- שאלות המשך.

המידע נשמר ב-localStorage של הדפדפן ולא בדאטאבייס.

## ניטור עלויות

AI Arena כוללת Cost Dashboard מקומי.
הדשבורד עוקב אחרי קריאות למודלים מתוך Compare Mode ו-Debate Club, ומציג שימוש לפי מודל בפועל.

הדשבורד מציג:

- הערכת עלות כוללת.
- מספר קריאות למודלים.
- הערכת input tokens ו-output tokens.
- שימוש לפי מודל.
- קריאות אחרונות.
- ייצוא CSV.

המערכת לא יודעת כמה כסף נשאר בחשבונות ה-API שלך. היא כן מחשבת הערכת עלות להרצות שבוצעו בתוך AI Arena.

מחירי ספקים לא מוגדרים בקוד כי הם משתנים. המשתמש מזין בעצמו מחיר נוכחי בדולר לכל מיליון input tokens
ולכל מיליון output tokens, לפי המודל שנבחר. ספירת ה-tokens היא הערכה מקומית לפי אורך טקסט,
ולכן היא מיועדת למודעות ובקרה ולא להתחשבנות מדויקת מול חשבונית הספק.

## Agent API

AI Arena כוללת מצב headless לסוכני AI ואוטומציות.
סוכן יכול לשלוח שאלה ל-API, להריץ Debate Club בלי לפתוח את ה-GUI,
ולקבל תשובה סופית ולוג מלא בפורמט JSON.

Endpoint:

```txt
POST /api/debate
```

דוגמה:

```bash
curl -X POST http://localhost:3000/api/debate \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -d '{
    "question": "מה אסטרטגיית התמחור הכי טובה למוצר?",
    "rounds": 3,
    "participants": ["chatgpt", "claude", "perplexity"],
    "judge": "grok"
  }'
```

אם מגדירים `ARENA_AGENT_TOKEN`, סוכנים חייבים לשלוח אותו כ-Bearer token.
זה מומלץ מאוד לפני פריסה ציבורית, כדי למנוע שימוש לא מורשה ושריפת קרדיטים.

## מקורות ואינטרנט

קריאות API רגילות למודלים לא בהכרח כוללות גלישה חיה באינטרנט.
Perplexity Sonar נתמך במיוחד כי הוא יכול להחזיר תשובות מבוססות חיפוש עם citations.

שאר המודלים מקבלים הנחיה:

- לא להמציא מקורות.
- לא להמציא URLs.
- לציין מה צריך לאמת אם אין להם גישה למידע עדכני.

## API Keys

הדרך המומלצת היא לשמור מפתחות בקובץ `.env.local` על המחשב:

```env
ANTHROPIC_API_KEY=
GOOGLE_API_KEY=
OPENAI_API_KEY=
XAI_API_KEY=
PERPLEXITY_API_KEY=
ARENA_AGENT_TOKEN=
NEXT_IGNORE_INCORRECT_LOCKFILE=1
```

אפשר להשאיר שדות ריקים. כל ספק הוא אופציונלי.

אפשר גם להזין מפתחות זמנית דרך כפתור `API Keys` בממשק.
מפתחות שמוזנים בממשק נשמרים רק ב-session של הדפדפן.

## הגדרות דיבייט לפני שליחה

לפני שמתחילים Debate Club אפשר להגדיר את מבנה הדיון:

- בחירת מספר סבבים.
- הפעלה או כיבוי של שופט חיצוני.
- בחירת איזה מנוע יהיה השופט.
- בחירת תפקיד לכל מנוע מתוך רשימת תפקידים מוכנה.
- כתיבת תפקיד מותאם אישית עם שם והנחיות חופשיות.

התפקידים נשמרים בלוג של הסשן, כך שאפשר להבין בדיעבד מי ענה מאיזו נקודת מבט.

אפשר לשנות את אותן הגדרות גם במהלך סשן דיבייט פעיל, לפני שאלת המשך:

- שינוי מספר הסבבים לשלב הבא.
- החלפה, הפעלה או כיבוי של השופט.
- שינוי תפקיד לכל מנוע.
- השארת מנוע בלי תפקיד ספציפי.
- שינוי לתפקיד מותאם אישית חדש.

שינוי הגדרות באמצע שיחה נרשם בלוג השקוף של הדיבייט, וההגדרות החדשות משפיעות על שאלת ההמשך הבאה.

## בחירת משתתפים ורפרנסים

בדיבייט לא חייבים להשתמש בכל המנועים שמחוברים. אפשר לבחור רק חלק מהם כמשתתפים, למשל 2 מתוך 3 או 2 מתוך 5, ולהחליט בנפרד אם יש שופט ומי הוא.

אפשר גם להוסיף Shared references / skills:

- הדבקת מידע על המשתמש, העסק, הפרויקט או ההעדפות.
- הדבקת כללים, סגנון כתיבה, מגבלות או ידע מקצועי.
- העלאת קבצי טקסט כמו `.txt`, `.md`, `.json`, `.csv`, `.yaml`, `.yml`.

הרפרנסים נקראים בדפדפן ונשלחים כקונטקסט למנועים שמשתתפים בדיבייט. הם לא מחליפים בדיקת עובדות, אבל עוזרים למודלים להבין את המשתמש והפרויקט טוב יותר.

## Ollama מקומי

AI Arena תומכת גם במודלי Ollama שרצים על המחשב, בלי API key:

- `qwen3:32b`
- `deepseek-r1:70b`
- `gemma4:latest`

כל אחד מהם מופיע כמנוע נפרד, כך שאפשר לבחור אותם בדיבייט או בהשוואה בדיוק כמו ספקי API חיצוניים. ברירת המחדל היא חיבור ל-`http://127.0.0.1:11434`.

במצב Compare אפשר לבחור בדיוק אילו מנועים ישתתפו בהשוואה, למשל רק `Ollama Qwen3 32B` מול `Ollama DeepSeek R1 70B`.

קובץ ההפעלה `start-ai-arena.bat` משתמש ב-`OLLAMA_HOST=http://127.0.0.1:11434` כברירת מחדל, ומנסה להפעיל `ollama serve` אם פקודת `ollama` זמינה ב-`PATH`.

אם המודלים של Ollama נמצאים בתיקייה מותאמת אישית, הגדירו את `OLLAMA_MODELS` בסביבה שלכם לפני ההפעלה.
